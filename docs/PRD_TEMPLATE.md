# 功能需求模板

## 背景和目标

说明现有流程的问题、目标用户，以及本次完成后用户能做什么。

## 范围

分别列出本次实现和明确不实现的能力，说明对现有功能的影响。

## 用户流程

按进入、操作、成功、失败、退出顺序说明用户看到的界面和系统行为。

## 具体需求

每项需求包含编号、输入、处理、输出及约束。注明数据来源、身份和状态变化。

## 异常处理

列出参数错误、权限不足、网络失败、数据为空和并发操作时的行为。

## 验收标准

使用“前提、操作、预期结果”定义可执行用例；区分接口与浏览器证据。

## 开发拆分

按依赖顺序列出可独立验证的任务及测试方式。

## 兼容和限制

说明已有数据及路由如何保留、演示账号来源、持久化和安全边界。
