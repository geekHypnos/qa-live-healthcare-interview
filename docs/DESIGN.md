本次在原项目上完成首页中英文切换、医生数据迁移和患者账号登录，不另起项目，不改技术栈。交付包括可运行的代码、需求与设计文档、真实测试报告、演示视频和 PR。完成标准以仓库 README 为准，不把文件已创建或页面能打开当作功能已完成。

方案日期：2026 年 10 月 21 日。当前状态：方案审核通过，待实施；尚未开始业务开发。审核结论仅针对需求覆盖和设计范围，不代表功能、测试、视频或 PR 已完成。

## 1 现有项目和改造范围

基线仓库为 `ups216/qa-live-healthcare-interview`，基线提交为 `4094c556c429889700be2accb34d224a8a2d6fd6`。

- 前端沿用 Vue 3、TypeScript、Ant Design Vue 和 Vite。
- 后端沿用 `server/qa-service-user` 的 Spring Boot 和 Java 17。
- 医生资料当前来自 `doctor-user-list.json`，首页、医生列表、医生登录和问诊页面都依赖同一个前端 store。
- 患者当前通过姓名和生日获得身份，找不到记录时会直接创建用户。这不属于密码登录，需要替换。
- 问题列表、提问和医生回复目前均为前端演示逻辑。本次不将整套问诊系统改造成生产服务。

### 本次必须完成

1. 首页右上角提供中文和 English 下拉选项，选择后立即切换。
2. 医生资料由 MySQL 保存，前端从用户服务读取，不再在接口失败时回退到医生 JSON。

### 不在本次范围内

不增加注册、找回密码、短信或第三方登录；不增加医生管理后台；不做全站翻译；不重构微服务、不引入 Redis、网关或消息队列；不新增支付、预约等业务。

患者和医生的提问、回复仍沿用原项目的前端模拟方式，刷新后新增问题可能丢失。持久化这些业务不是本题要求。登录身份由服务端确认，但前端演示问题数据不因此成为受服务端权限保护的真实医疗记录；README 和演示说明需明确这条边界。

## 3 首页中英文切换

右上角语言下拉框放在现有页头中，只在首页显示。默认使用中文，用户选择保存在浏览器中，刷新后恢复；本地存储不可用时仍能正常切换。进入其他页面后维持原有中文界面，不要求翻译其他业务页面。

资源使用 `locales/zh-CN.ts` 和 `locales/en-US.ts`，通过小型、带类型的语言状态模块读取。当前只有一个页面需要翻译，不额外引入完整的国际化框架，也不为语言功能更换现有 store。

翻译覆盖首页标题、介绍、三个服务特点、导航、操作按钮、统计项、诊室区域、在线状态、加载和失败提示，以及首页可见的页脚内容。语言选项始终显示“中文”和“English”，便于切回。

医生列表的数据源仍是 MySQL。首页已有演示医生的姓名、职称、科室、经验和专长可通过语言资源中的文本映射提供英文展示，不再复制一份带登录信息的医生 JSON。英文不存在对应翻译时保留原始内容，不隐藏该医生，也不自动调用外部翻译服务。原题要求的英文验收针对初始化的演示内容完整检查。

切换时不重新加载页面，不改变医生 ID、路由和统计值；英文文案不能撑坏右上角导航或诊室卡片。

## 4 医生数据和数据库

### 数据组织

使用三个必要的数据实体，不建立通用权限平台：

- `doctors`：保留原有医生 ID、username、姓名、职称、科室、头像、经验、专长和开放状态。
- `patients`：保留原有患者 ID 和必要展示信息，用于关联原问题记录。
- `accounts`：保存唯一用户名、BCrypt 密码哈希、角色和对应资料 ID。角色只包括 PATIENT 与 DOCTOR，不提供由调用方自由选择的授权能力。

专长作为有序列表保存，返回前端仍为 `string[]`，不为这份小型演示数据增加专长管理体系。公开医生响应中不包含账号表字段、密码或哈希。

原有医生明文密码只用于一次性迁移演示账号，不继续发布到前端资源。患者配置两个及以上可区分的演示账号，关联已有患者 ID，便于验证切换用户后问题列表不会串号。演示凭据与真实数据库密码分开说明，不复用任何个人账号。

### 启动和初始化

根目录 Compose 启动 MySQL 与 phpMyAdmin，数据通过命名卷保存。MySQL 使用 utf8mb4，避免医生姓名和专长出现乱码。镜像使用明确的兼容版本标签，在实现和测试时记录实际版本，不用 `latest`。

数据库应用账号只授予项目库所需权限，不让 Java 服务使用 root。数据库和管理端口只绑定本机，凭据经环境变量传入，提交 `.env.example`，不提交个人 `.env`。phpMyAdmin 提供登录入口，不在前端界面中嵌入管理凭据。

SQL 包含建表和稳定的演示数据。初始化区分两种情况：首次创建空卷时自动导入；已有卷按文档显式执行更新步骤。重复执行不会重复插入相同账号和医生。常规启动和测试不执行删除卷操作，清空演示环境须单独说明并由使用者主动选择。

Java 服务使用 Spring JDBC 和参数化 SQL。此处查询与账号校验较少，不增加 ORM、通用 DAO 基类和完整迁移平台。

### 前端接入

公共 store 负责加载医生资料，首页、医生列表和问诊选医生复用同一数据源，避免各页面重复维护不同的数据。应用初始化加载一次，接口失败时显示错误并允许重试；空数组与请求失败分别处理。

保留医生 ID 和 username，因此 `/consultation/:doctorUsername` 与原问题关联无需改名。直接打开带医生 username 的问诊链接时，先等待医生加载完成，再判断医生是否存在或开放，避免把尚未加载当成查无此人。医生不可用时给出提示，不允许静默选中其他医生。

## 5 患者登录和医生兼容

### 患者流程

替换问诊页现有的姓名和生日表单，使用用户名、密码和提交按钮，不另外创建一个与问诊流程脱节的登录入口。去掉旧入口的自动开户逻辑，不能继续通过姓名生日获取患者身份。

正确登录后展示患者姓名，并使用服务端返回的患者 ID 过滤原有问题、关联新问题。请求过程中禁止重复提交；账号不存在与密码错误使用同一提示“用户名或密码错误”，网络异常和服务不可用单独提示。

页面启动时查询当前会话。在完成查询前显示恢复状态，避免短暂出现错误身份或错误登录页。刷新后身份保持；退出时由服务端销毁会话，同时清除前端身份、尚未提交的表单和弹窗。会话过期后回到未登录状态，不保留可继续使用的患者身份。

会话校验不能只发生在页面启动时。页面从后台恢复可见、进入需要登录的问诊或诊室页面，以及实际提交问题、医生回复或标记已解答之前，都调用 `/api/auth/me`。提交前的检查必须等待响应，并确认角色和资料 ID 仍与当前操作一致，再修改前端演示数据；不能先修改数据再补查身份。

收到 401 时清除患者和医生身份、未提交表单、选中的问题及弹窗，回到相应登录入口，并提示重新登录。若返回的是另一个账号或角色，也中止本次操作并清理旧身份状态。网络异常或服务不可用时保留数据不变、阻止本次提交并允许重试，不将它们当作校验成功，也不错误提示为密码错误。不增加定时轮询，空闲页面在下一次上述事件发生时发现会话失效；这些检查用于保持演示流程一致，不改变第 1 节关于前端模拟数据的边界。

### 医生兼容

医生原登录页面和诊室路由保留，登录改为后端验证，不再从公开医生资料中查找密码。医生身份与账号角色由数据库决定，前端不能通过修改请求字段把患者升级成医生。登录为另一角色或另一个账号时，替换原身份并清理前端状态；本方案不支持同一浏览器会话同时登录两种角色。

医生退出同样使服务端会话失效。诊室页面校验当前会话中的医生 username 与路由一致，不允许医生 A 在页面中使用医生 B 的身份。原有前端演示回复功能继续保留，其非生产级数据边界见第 1 节。

### 会话处理

使用 Spring Security 的认证与会话能力，单实例使用内存会话，不增加 Redis，也不实现 JWT 刷新体系。会话超时采用 30 分钟空闲过期；后端重启需重新登录，在运行说明中写明。

会话 Cookie 使用 HttpOnly 和 SameSite=Lax；HTTPS 环境设置 Secure，本地 HTTP 演示不强制 Secure。登录成功更新会话 ID，退出销毁会话。写操作启用 CSRF 校验，不能为了方便 curl 测试整体关闭。

Vite 将 `/api` 代理到用户服务，让前端使用同源相对路径。删除本次认证接口依赖的任意来源携带凭据配置；不以通配 CORS 绕过会话问题。密码不写日志、不进 URL、不存浏览器 localStorage。

## 6 接口约定

| 方法 | 路径 | 用途 | 访问要求 |
| --- | --- | --- | --- |
| GET | `/api/doctors` | 返回公开医生列表 | 无需登录 |
| GET | `/api/auth/csrf` | 获取当前会话的 CSRF token 和请求头名称 | 无需登录 |
| POST | `/api/auth/login` | 接收 username 与 password，返回由账号决定的身份 | 携带 CSRF token |
| GET | `/api/auth/me` | 获取角色及当前资料 | 已登录，否则 401 |
| POST | `/api/auth/logout` | 注销当前会话 | 携带 CSRF token |

医生列表返回原前端需要的字段。登录和当前身份响应使用明确的角色、账号 ID 及对应医生或患者资料，不返回密码哈希。前端按返回角色判断当前入口是否可用，不能仅凭客户端保存的标志判断认证成功。

返回状态统一为：成功 200；不合法的参数或 JSON 为 400；登录失败或会话不存在为 401；缺少或错误的 CSRF token 为 403；服务内部错误为 500。错误体只包含稳定的错误标识和可读消息，不返回 SQL、堆栈或数据库连接信息。

前端和 curl 均通过 Cookie 保存会话。登录、退出后按服务端行为重新获取 CSRF token，测试不能依赖过期 token。数据库不可用时医生接口返回明确错误，不能伪造成功列表。前端展示失败状态并提供重试。

现有测试 Controller 和 Actuator 先做基线检查。本次不扩大调试接口；与认证运行环境有关的管理端点只暴露必要的健康信息，不继续公开 env、beans、loggers 等调试数据。

## 8 测试和完成标准

### 构建和自动化检查

后端覆盖医生查询、公开字段过滤、账号与密码验证、会话恢复、角色、退出、参数错误和 CSRF。真实 MySQL 联调用 curl 测试补足，不能用内存替身的结果替代数据库验证。

前端完成类型检查、生产构建和关键状态测试，包括提交前会话检查失败时不修改模拟问题数据。构建通过不能替代下面三类验收，报告分别记录各类证据。

### 接口验收

以下五个接口全部使用 curl 测试，保存状态码和响应断言结果；Cookie jar、CSRF token 和登录步骤按 `API_TEST.md` 执行：

| 接口 | 必查结果 |
| --- | --- |
| `GET /api/doctors` | 初始化医生数据和字段完整，专长为数组，响应无 password 或 passwordHash |
| `GET /api/auth/csrf` | 返回非空 token 和请求头名称，配合 Cookie 可用于后续请求 |
| `POST /api/auth/login` | 患者及医生正确登录；未知账号和错误密码返回相同的 401 错误；空参数、超长输入、非法 JSON 返回 400；缺少或错误 token 返回 403 |
| `GET /api/auth/me` | 未登录、失效或已退出会话返回 401；已登录时角色和资料 ID 正确；切换账号后返回新身份，患者不能得到医生角色 |
| `POST /api/auth/logout` | 带有效 token 和 Cookie 退出成功；退出后旧会话不能取得身份；缺少或错误 token 返回 403 |

登录、退出后重新取得 CSRF token，再验证后续请求，不能复用失效 token。接口验收证明响应和会话行为，不用于证明浏览器页面正确展示。

### 浏览器验收

1. 首页正文、页头和页脚能完整切换中英文，刷新恢复选择，窄屏和英文长文本无明显溢出。
2. 医生列表、首页和问诊选医生使用后端数据；加载失败可重试，空列表不显示为网络错误，直接进入医生链接会等待数据加载。
3. 患者正确登录、错误提示、刷新恢复、退出和账号切换符合 PRD；姓名生日旧入口不再能获取身份。
4. 医生登录、诊室路由身份校验、演示回复和退出没有因迁移失效。
5. 页面保持打开且不刷新时，让会话过期或在另一标签页退出；随后提交问题、医生回复或标记已解答，验证操作被阻止、模拟数据未变化、身份及草稿已清理。
6. 验证页面恢复可见时会重新检查会话；提交前检查返回网络错误或其他账号身份时，不执行原操作，也不显示提交成功。

会话超时测试可在独立测试配置中缩短超时时间，记录实际配置，正常运行仍保持 30 分钟。浏览器验收保存实际截图或操作记录，不以 curl 通过推断页面通过。

### 数据库和环境验收

1. MySQL 与 phpMyAdmin 可以启动和登录；初始化 SQL 重复执行不产生重复账号和医生。
2. SQL 查询与 `/api/doctors` 响应对应。修改一条演示医生资料后，重新请求接口并刷新医生页面，分别保存数据库、接口和页面证据，最后恢复原值。

## 10 实施顺序和退出条件

本轮方案审核已通过，下一步为简短环境检查。后续顺序为：生成 PRD 模板和登录 PRD → 生成实施计划 → 验证项目基线 → 数据库与医生接口 → 患者登录与医生兼容 → 首页翻译和前端联调 → 依据测试文档执行三类验收 → 录制视频 → 推送、上传附件并创建 PR。
