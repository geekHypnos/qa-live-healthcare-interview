# 患者用户名密码登录需求

## 背景和目标

现有问诊入口只凭姓名和生日确认身份，未知用户会自动创建账户。改为服务端验证的用户名密码登录，使用户刷新页面后可以恢复身份，退出后不能继续使用原身份操作。

## 范围

本次提供预置账号登录、会话恢复、退出、失效处理及原问诊衔接。医生资料迁出前端后，医生登录同步改为服务端校验以避免功能回归。不新增注册、密码找回、第三方登录或权限管理后台。

## 用户流程

打开问诊页后先恢复会话。未登录时输入用户名和密码；正确则显示患者姓名和本人演示问题，错误则保留登录页并提示“用户名或密码错误”。登录后可以选择医生、查看原问题、提交演示问题。刷新保留身份，退出清除身份与草稿。旧姓名生日表单及自动开户停用。

## 具体需求

- LOGIN-01：用户名去除首尾空白后为 1 到 64 个字符；密码为 1 到 128 个字符，不对密码做 trim。服务端验证 JSON 类型及长度；BCrypt 接受的密码最多 72 个 UTF-8 字节，超出时返回参数错误。
- LOGIN-02：账号保存在 MySQL，密码为 BCrypt 哈希，不返回前端、不写日志。数据库决定 PATIENT 或 DOCTOR 角色，不接受客户端提升角色。
- LOGIN-03：成功返回角色、账号 ID 和资料；患者资料保留 patient001 等既有 ID。演示患者账号为 patient001、patient002，密码均为 Patient123!；医生保留 dr-zhang-wei 等原用户名，演示密码为 123456。这些仅用于本地演示，不能用于公开部署。
- LOGIN-04：单浏览器会话仅有一个身份。切换账号替换旧身份；登录成功更新会话 ID，空闲 30 分钟过期，服务重启需重新登录。
- LOGIN-05：页面进入、恢复可见及每次模拟写操作前查询服务端身份，确认角色与资料 ID 一致后才修改数据。不增加轮询；网络失败阻止操作并允许重试。
- LOGIN-06：退出销毁服务端会话，清除客户端患者与医生身份、草稿和弹窗。401 或发现其他身份同样清理旧状态并要求重新登录。
- LOGIN-07：医生登录页面与诊室路由保留；医生只能以服务端身份进入自己的诊室。
- LOGIN-08：接口使用同源 Cookie 和 CSRF，前端不保存密码。登录、退出后更新 CSRF token。

## 异常处理

错误凭据和未知账号统一返回 401。非法参数或 JSON 返回 400。CSRF 缺失或无效返回 403。网络、数据库故障显示服务错误，不伪造身份、不自动创建账号。按钮在请求过程中不可重复提交。

## 验收标准

| 前提 | 操作 | 预期结果 |
| --- | --- | --- |
| 未登录 | 查询 me | 401 |
| 有有效 CSRF | 使用正确患者凭据登录 | 200，角色 PATIENT，保留原患者 ID |
| 正确会话 | 刷新问诊页面 | 恢复患者姓名和原有问题 |
| 未登录 | 错密码或未知账号 | 同样的 401，不创建账户 |
| 任意状态 | 空参数、超长或类型错误输入 | 400，无异常堆栈 |
| 无有效 CSRF | 登录或退出 | 403 |
| 已登录 | 退出再查 me | 退出成功，me 为 401 |
| 页面仍开着 | 会话过期后提交问题或医生回复 | 中止，数据不变，清理旧身份及草稿 |
| 身份校验网络失败 | 提交演示操作 | 中止，可重试，不显示成功 |
| 医生 A 已登录 | 打开医生 B 的诊室路由 | 拒绝使用医生 B 身份 |
| 患者已登录 | 尝试进入医生诊室 | 不赋予医生身份 |

接口用 curl 验收，页面恢复及草稿行为用浏览器验收，不相互替代。

## 开发拆分

1. 初始化账号和患者资料，保留既有 ID，检查哈希与公开字段。
2. 先写认证失败测试，再实现 login、me、csrf 和 logout。
3. 前端接入会话与登录表单，移除旧验证与前端密码。
4. 加入操作前身份检查及医生兼容，测试过期与网络失败。
5. 依据 API_TEST 执行接口测试，再做浏览器回归和录制。

## 兼容和限制

本需求依据 PRD_TEMPLATE 编写，技术约束以 DESIGN 为准。既有问题仍为前端演示数据，新增提问或回复刷新后不保证保留；本次不将它们描述为安全持久化的真实医疗记录。医生列表数据和账号数据必须来自 MySQL，不在失败时回退到浏览器密码或姓名生日验证。
